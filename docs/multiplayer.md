# NEXUS Multiplayer / protocol 1

NEXUS использует общие аккаунты Auth.js, библиотеку PostgreSQL и отдельный долгоживущий Node.js/Colyseus 0.18 процесс. Основной регион — Europe. В первой версии один игровой сервер; Redis не требуется. Активные комнаты, присутствие и симуляция живут в памяти этого процесса. Друзья, блокировки, группы, приглашения, участники, результаты и статистика — в PostgreSQL. Позиции в базу не записываются.

## Локальный запуск

После `npm ci`, `node scripts/init-env.mjs`, запуска PostgreSQL, миграций и seed:

```bash
# Терминал 1 — игровой процесс
npm run game:dev
# Терминал 2 — веб-консоль
npm run dev
```

Или `docker compose up -d --build --wait game-server` вместо первого терминала. Сначала примените миграции. Одновременно запускайте только один игровой процесс для данной базы. В облачной среде этого проекта используйте `sh scripts/cloud-compose.sh up -d --build --wait game-server`: wrapper передаёт существующий HTTPS proxy и его публичный CA только в сборку, с сохранением проверки TLS. Порт сервера 2567, web 3000, `/health` сообщает готовность процесса.

`MULTIPLAYER_SECRET` — отдельный общий секрет только для backend и игрового сервера (минимум 64 символа). `init-env.mjs` добавляет отсутствующие настройки, не заменяя действующие ключи. `MULTIPLAYER_INTERNAL_URL` доступен только backend. `NEXT_PUBLIC_MULTIPLAYER_URL` — открытый адрес транспорта, секретом не является.

## Проверка двумя людьми

1. Создайте два разных аккаунта в двух браузерах/на двух компьютерах. Каждый самостоятельно добавляет MIDNIGHT OUTLAWS в библиотеку.
2. В Friends найдите username, отправьте запрос и примите его во втором аккаунте.
3. Откройте «Онлайн-гонка», создайте приватную комнату и пригласите друга. Во Friends второго аккаунта появится настоящее приглашение.
4. Присоединитесь, выберите автомобили, подтвердите готовность. Лидер начинает заезд, только когда подключены минимум два готовых игрока.
5. Оба управляют собственной машиной. Финиш и позиции определяет сервер; результаты появляются у всех и в истории Friends. Лидер может предложить повторный заезд.

Быстрый матч ищет публичное лобби того же gameId и режима circuit с достаточным количеством мест. Если подходящего нет, создаёт новое. При отсутствии второго игрока старт запрещён; пользователь видит ожидание и может отменить поиск, пригласить друга или открыть одиночную тренировку. Никаких искусственных «живых игроков» и подставных онлайн-счётчиков нет. В Europe сейчас один регион: подбор между регионами и по рейтингу не реализован.

Группа хранится на сервере, максимум шесть участников. Лидер запускает групповой поиск, остальные входят в выделенное ей лобби через экран поиска группы. На время подключения места группы резервируются на 60 секунд. Все участники должны иметь игру в библиотеке. Групповой поиск не начинает матч без согласия Ready каждого игрока.

## Граница доверия

- Изменяющий Next API проверяет Auth.js cookie, внутреннее истечение сессии, tokenVersion, Origin и лимит частоты. Клиент не выбирает userId.
- Backend вызывает внутренний `/control` с HMAC-SHA256 токеном: sub, ver, kind, aud, iat, exp, jti. Срок — 45 секунд. Подпись сравнивается за постоянное время. Control jti одноразовый, кэш очищается по сроку.
- Игровой сервер повторно проверяет пользователя и tokenVersion, библиотеку, зарегистрированный runtime, блокировки, приватность, вместимость и правила группы. Возвращает одноразовую Colyseus seat reservation для конкретного пользователя и комнаты.
- Прямые HTTP matchmaker-запросы защищены static onAuth; прямое создание без подписанного разрешения запрещено. Socket admission снова проверяет базу и комнату. Reservation живёт 20 секунд. Room code не обходит приглашение приватной комнаты.
- Сессионный cookie Auth.js, пароль и ключ подписи не передаются игровому runtime. Reservation/reconnection token хранятся только в памяти SDK, без localStorage. По коду комнаты нельзя получить чужой токен.
- Входящие WebSocket сообщения ограничены 2048 байт и 80 сообщениями в секунду на клиента. Zod принимает только конечные throttle/brake [0,1], steer [-1,1], nitro:boolean и монотонный seq. Поля позиции, скорости, времени, победителя и client dt запрещены. Повторные/опоздавшие seq игнорируются, невозможные диапазоны и явные нарушения отклоняются.
- Сервер сам применяет ускорение, нитро, трение, границы трассы, порядок контрольных точек и финиш. Старт атомарно меняет фазу до await; запись результатов идемпотентна и выполняется транзакцией. Клиент не отправляет соревновательные результаты.
- Приглашения живут пять минут, ограничены по частоте. Нельзя пригласить заблокированного пользователя или обойти его настройки приватности. При входе учитываются актуальные блокировки и приглашения.

## Синхронизация

Общая чистая физика находится в `src/games/racing-physics.ts`, сетевые контракты — `src/multiplayer/contracts.ts`. Симуляция сервера работает с фиксированным шагом 1/30 с; снимки отправляются 15 раз в секунду. На один server tick применяется последний допустимый ввод, а не произвольное количество присланных клиентом шагов. После 250 мс без ввода машина перестаёт получать газ.

Клиент предсказывает собственное движение немедленно, хранит ограниченную очередь команд и пересчитывает её поверх авторитетного состояния с ack sequence. Малые визуальные поправки сглаживаются; большая рассинхронизация сбрасывается. Удалённые машины отображаются через буфер снимков с задержкой 120 мс, интерполяцией положения и угла и экстраполяцией максимум на 100 мс. Снимки со старым временем не применяются. RTT и jitter измеряются через ping/pong; качество сети видно в HUD.

Физика отделена от React и Three.js. `RaceNetworkDriver` связывает предсказание и визуализацию. Контактных столкновений между машинами нет: это полноценная гонка с серверным финишем в режиме ghost racing. Столкновения с ограждением симулируются одинаковой физикой.

После временного обрыва Colyseus резервирует прежнее место на 30 секунд и автоматически переподключает SDK с ограниченным backoff. На переподключении повторно проверяется tokenVersion. Недоступный игрок виден в лобби; после истечения окна его место освобождается, в гонке он получает DNF. Лидерство лобби передаётся следующему подключённому участнику. Онлайн-матч нельзя ставить на паузу: меню тормозит собственную машину, но не останавливает общий сервер.

Перезапуск процесса теряет активные комнаты. Незавершённые матчи помечаются ABORTED при следующем старте; победы не выдумываются. Завершённые результаты сохраняются PostgreSQL. Резервирование результата в памяти повторяет запись при временном отказе базы; после аварийного завершения до записи результат может быть потерян. Восстановление активной симуляции между процессами — дальнейшее расширение.

## Presence и приватность

Авторизованный heartbeat отмечает контакт с сервером; статус вычисляет сервер. Online истекает через 40 секунд без heartbeat, Away — после двух минут без взаимодействия. Членство в живой комнате определяет In Lobby / In Game. Социальный интерфейс получает обновления polling-запросами, обычно раз в 5 секунд (фоновое уведомление — 15 секунд), а не выдуманными данными. Скрытое присутствие возвращается друзьям как Offline; запрет показа игры убирает roomId/gameId. Поля произвольного статуса с клиента не принимаются.

## SDK и следующая игра

`src/multiplayer/sdk.ts` предоставляет authenticate, createRoom, joinRoom, leaveRoom, quickMatch/cancelSearch, invitePlayer, startMatch, sendInput, receiveState, reconnect, endMatch и submitServerVerifiedResult. Последний метод читает подтверждение сервера; публичного API загрузки результата от клиента нет. `endMatch` для клиента означает выход, а не назначение победителя.

Manifest объявляет singlePlayer, onlineMultiplayer, localMultiplayer, coop, competitive, maxPlayers и поддержку приватных комнат, матчмейкинга и переподключения. Кнопка онлайн-игры появляется только для зарегистрированного реализованного адаптера.

Чтобы подключить следующую онлайн-игру:

1. Зарегистрируйте обычный runtime по [Game Runtime](game-runtime.md), укажите только реально реализованные capabilities.
2. Реализуйте чистую детерминированную симуляцию, строгую схему ввода, авторитетные условия завершения и типы состояния. Не принимайте клиентские позиции или результаты.
3. Добавьте проверенный Colyseus room/адаптер в явный серверный registry. Используйте общие admission tokens, account ids, friends/party/invite правила, rate limits и durable match tables; не создавайте второй набор аккаунтов.
4. Подключите игровой драйвер к общему транспортному SDK. Для другого типа состояния добавьте типизированный протокол/адаптер предсказания и визуализации, оставляя учётные записи и социальные API общими.
5. Напишите интеграционный тест двух настоящих клиентских сессий, server settlement и reconnect. Только после успешных проверок включайте onlineMultiplayer.

Новые режимы могут подключать отдельные зарегистрированные room-классы; arbitrary JS/ZIP, серверные пути и команды из админки не допускаются. Лицензированный внешний сетевой движок в будущем может иметь адаптер к общим аккаунтам и приглашениям, но такой адаптер сейчас не реализован.

## Production WSS

`compose.production.yaml` и `deploy/Caddyfile` поднимают web, игровой процесс и TLS reverse proxy с отдельными DNS-именами. Укажите реальные `NEXUS_DOMAIN`, `NEXUS_GAME_DOMAIN`, HTTPS `NEXTAUTH_URL` и WSS `NEXT_PUBLIC_MULTIPLAYER_URL`, откройте 80/443 для выдачи сертификатов Caddy. Соберите web с тем же публичным адресом игры: Next встраивает NEXT_PUBLIC переменные при сборке.

```bash
# После создания .env с production значениями:
docker compose -f compose.yaml -f compose.production.yaml build
docker compose up -d --wait db
docker compose -f compose.yaml -f compose.production.yaml run --rm --no-deps game-server npm run db:migrate
docker compose -f compose.yaml -f compose.production.yaml run --rm --no-deps game-server npm run db:seed
docker compose -f compose.yaml -f compose.production.yaml up -d
```

Публичный production URL без WSS останавливает игровой процесс при запуске. Исключение — оба адреса loopback для локальной production-проверки. CSP разрешает только настроенный origin игры и соответствующий HTTP origin, без широкого разрешения `wss:` в production. Игровой порт не публикуется напрямую в production override. Нужны реальные домены: внешнее TLS-развёртывание не имитируется локальным WS.

## Метрики и масштабирование

`GET /api/admin/multiplayer` доступен только ADMIN. Возвращает activePlayers, activeRooms, concurrentMatches, simulation tick average/max, ticks, входящие messages и throughput, disconnects, reconnects и долю успешных восстановлений. Эти числа получены из живого процесса, сбрасываются при перезапуске. Tick duration измеряет симуляцию, не всю стоимость рендера/сети/БД. PlayerRating хранит реальные races/wins; MMR пока не рассчитывается и не используется в поиске.

Перед несколькими инстансами нужно добавить Redis Presence/Driver Colyseus, распределённый admission/match allocation, межпроцессный presence, региональные адреса и владение match rows конкретным процессом. Текущее startup-восстановление ABORTED рассчитано на одного владельца; просто запускать несколько копий против одной базы нельзя. Голосовой чат, рейтинговый подбор и миграция живых комнат не входят в эту версию.

Фактические прогоны находятся в [multiplayer-test-results.json](multiplayer-test-results.json); условия и ограничения — в [validation.md](validation.md). Локальная симуляция задержки не доказывает качество на любом расстоянии или любом GPU.
