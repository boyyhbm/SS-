# MIDNIGHT OUTLAWS — City Online & Driving update

Доработка существующего runtime. NEXUS Console, аккаунты, личные библиотеки, друзья, роли и исходные сохранения сохранены. Публичный адрес — https://nexus-web-ylcv.onrender.com. Все четыре маршрута проверены двумя независимыми браузерами по HTTPS/WSS; [сохранённые серверные записи](public-route-records.json) и [сохранность данных после реального rollout](public-tests.json) подтверждены.

## Игровые изменения

- Один Route Registry для одиночной игры и Colyseus: Downtown Circuit, Midnight Sprint, Industrial Run и сохранённое Original Night Circuit. Версия, геометрия, стартовая решётка, ворота, финиш и число кругов передаются сервером. Хозяин выбирает трассу в лобби, смена настроек снимает готовность; гости видят одинаковую конфигурацию. Несовместимая версия отклоняется.
- Сервер проверяет последовательность ворот, круги, финиш и результаты. Общая физика используется клиентским предсказанием и сервером. В PostgreSQL сохраняются ID/версия трассы, круги и фактический контактный режим. Старые матчи получают исходный `legacy-circuit`; это три добавочных миграции без удаления таблиц или записей.
- Траектория рассчитывает кривизну, приблизительное сцепление и обратный тормозной профиль. Цвет зависит от скорости и оставшегося расстояния. Прозрачные стрелки повторяют сглаженный путь с проверенным запасом до бордюров; геометрия создаётся один раз на маршрут, в кадре меняются цвета. Off / Corners Only / Full; Corners Only — по умолчанию. Выбор хранится на сервере в аккаунте, работает в одиночной и сетевой игре.
- Контакты с окружением: масса, инерция, нормальный и касательный импульсы, трение, скольжение и реакция угла кузова. Проверяется движение капсулы между позами с шагом не более 15 см, включая вращение; попадание уточняется двоичным поиском. Обратный ход и скольжение после касания не блокируются.
- Есть отдельный серверный решатель контактов машин с тремя подшагами на тик. Он проверен SDK-сессиями и двумя браузерами в изолированной приватной комнате. **В production он выключен** (`NEXUS_PRIVATE_CAR_CONTACTS=0`): при моделируемых 100–200 мс p95 ошибки коррекции около 0,9 м; устойчивость изображения на физическом GPU и реальных WAN-маршрутах ещё не подтверждена. Без серверного флага кнопка режима скрыта. Публичные гонки работают без контактных столкновений игроков.

## Причины рывков и исправления

Первый диагностический круг показал 69 из 126 кадров, где расчёт интерполяции опережал таймер физики. Рендер несколько раз повторял старую позу, затем показывал догоняющие шаги. Теперь перед показом кадра обрабатывается прошедшее время через единые часы симуляции. Независимый таймер ввода/сети использует те же часы и не удваивает шаги. Предыдущее и текущее состояния интерполируются в переиспользуемый визуальный буфер; физика не получает эти промежуточные позы.

Позиция, угол, руление и скорость интерполируются совместно. Камера использует ту же позу, кратчайшую дугу угла и delta time; сетевые коррекции сглаживают также угол. Стандартная дистанция 7,8 м и FOV 58° не зависят от скорости. Проверка препятствий начинается у машины, а не в точке взгляда впереди; тонкий столб не вызывает приближение, если камера физически к нему не подходит. Выход из укороченного положения ограничен по скорости. Убраны постоянная копия drawing buffer и необязательное измерение GLB-границ из обычного кадра.

F3 открывает Developer Overlay: FPS, эмпирический 1% low, средний/p95/максимальный кадр, время физики и отправки рендера, число draw calls, буфер интерполяции и возраст последнего снимка по оценке серверных часов. Пауза исключена из статистики активных кадров. Вращения через ±180° и интерполяция проверяются при 30/60/120 Гц; это не аппаратное измерение дисплея.

## Графика

Существующие лицензированные Car Concept и Bistro GLB сохранены. Настроены лак, карбон, шины и диски; фонари плавно меняются только при выходе соответствующего объекта из ближайшего набора. Перестановка расстояний не переносит уже работающий свет. Карта теней привязана к сетке текселей. Добавлены редкие оригинальные следы шин и трещины на выбранных участках; отражения остаются PBR/HDR без нового зеркального прохода. Low получил более дешёвое освещение фасадов и отключённый MSAA; High сохраняет физические материалы. Для LOD добавлен гистерезис. Motion blur/TAA не включены.

Разрешение исходных фасадных текстур не увеличивалось и апскейлинг за детализацию не выдаётся. Город остаётся компактным прототипом: есть глухие фасады и открытые кварталы, нет пешеходов и городского трафика. Физического игрового ПК и USB/Bluetooth-контроллеров в среде нет. **High/1080p/60 FPS не сертифицированы.**

Все изображения и записи получены из запущенного браузера. Скорость воспроизведения не ускоряется, промежуточные кадры не синтезируются. Частота кодирования MP4 не является FPS игры. Для функциональных сетевых записей используется Low с указанным в отчёте DPR; графические снимки отдельно сделаны на High. Видеозаписи на SwiftShader подтверждают действия и результат, а не плавность физического GPU. Дополнительный прогон приватных контактов при DPR 0,5 **не прошёл**: один клиент потерял соединение и вернулся в browse с кодом 4003. [Отчёт неуспешного прогона](higher-resolution-contact-attempt.json) сохранён; точная причина этого разрыва не установлена. Ранее успешные SDK/браузерные проверки при DPR 0,15 не заменяют эту проверку и не сертифицируют контакты для публичного режима.

```bash
# Изолированная локальная QA-база и запущенные Web/Colyseus:
npm run test:city-multiplayer
NEXUS_TEST_CONTACTS=1 NEXUS_TEST_NETWORK=1 npm run test:city-multiplayer
# База должна иметь имя nexus_gameplay_qa_<8 hex>; основная база не допускается.

TEST_BASE_URL=http://localhost:3001 NEXUS_QA_OUTPUT=docs/gameplay-update node --experimental-strip-types scripts/qa-city.ts smoothness
# Другие режимы: screens, camera, video, collision, performance.
```

Временные фикстуры создают собственные аккаунты и удаляют только свои записи. Закрытые credential ledger, cookie и резервные копии в Git не включаются. Итоговые статусы CI, публичных проверок и измеренные показатели приведены в связанных отчётах.

Полный CI создаёт более 30 аккаунтов с одного адреса. Для последнего сценария регистрации используется явно включаемая изоляция только точного `register:shared` quota в одноразовой локальной CI/QA-базе (`NEXUS_E2E_DISPOSABLE_DB=1`). Production-лимиты не меняются: [реальные 30 запросов и HTTP 429 на 31-м](registration-rate-limit.json). Тестовый автопилот освобождает свои кнопки один раз при переходе в меню, чтобы не перезаписывать контроллерные команды интерфейса.

[Полный CI: 117 unit и 24 браузерных сценария](https://github.com/boyyhbm/SS-/actions/runs/40240880798) прошёл для опубликованного приложения `e3773ef`. Последний commit с отчётами, медиа и разрешением legacy в проверочном скрипте не меняет код приложения и не вызывает повторный rollout. Исходное кольцо проверено теми же публичными assertions через вариант скрипта с расширенным whitelist; новый whitelist также сохранён в основном инструменте.
