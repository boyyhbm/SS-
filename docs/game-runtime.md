# Game Runtime

## Что зарегистрировано

`src/games/registry.ts` содержит типизированный `GameManifest` и единственный доступный runtime `midnight-outlaws`. Manifest включает id, slug, title, description, genre, cover, banner, screenshots, runtimeType, entrypoint, supportedInputs, supportedPlatforms, version и status. Запись `Game` в PostgreSQL содержит редактируемые описания и ссылку `runtimeKey`; manifest определяет допустимый исполняемый модуль.

Сервер `isPlayable()` разрешает запуск только при одновременном выполнении условий: карточка опубликована, её статус AVAILABLE, runtimeKey присутствует в явном реестре и runtime имеет статус available. `GameRuntimeHost` выбирает адаптер из `src/games/players.tsx`, а тот загружает проверенный внутренний модуль через статический dynamic import. Общий контекст содержит gameId, название, язык и собственные сохранения; HUD и интерпретация результата принадлежат игре. Администратор не управляет импортом или серверным путём.

## Следующая внутренняя игра

1. Создайте независимый модуль в `src/games/<key>/`. Не импортируйте серверные модули, Prisma, Auth.js или секреты.
2. Опишите manifest в registry: оригинальные artwork, реальные supportedInputs и supportedPlatforms, версию, runtimeType, фиксированную точку входа.
3. Добавьте ключ в серверную Zod-схему `gameSchema.runtimeKey`, клиентский select админки и статический адаптер в `src/games/players.tsx`. Используйте существующий общий `GameRuntimeHost` и независимый HUD с адаптером к типизированным `RuntimeEvents`.
4. Реализуйте ready/error/lap-or-result/dispose callbacks. `onReady` должен следовать реальному первому кадру или загрузке ресурсов, а не таймеру.
5. Освобождайте event listeners, requestAnimationFrame, renderer, GPU geometry и материалы при выходе. Пауза обязательна при скрытии вкладки и потере фокуса.
6. Для новых типов сохранений добавьте отдельную серверную схему проверки. Сервер определяет userId по сессии, проверяет библиотеку и активную сессию. Не принимайте произвольные JSON без лимита размера и версии схемы.
7. Добавьте модульные проверки логики и браузерный smoke-тест запуска и выхода.
8. Создайте карточку в `/admin`, выберите новый зарегистрированный runtime и опубликуйте. Автоматическое добавление в библиотеки запрещено.

Существующий прототип отправляет только время круга и идентификатор собственной сессии. Сервер проверяет принадлежность, допустимый диапазон, прошедшее время, сохраняет минимум и не удаляет сохранения при удалении членства в библиотеке.

## Будущие внешние сборки

`FutureRuntimeAdapter` описывает форму расширения для React Canvas, WebGL, WebAssembly, WebGPU и внешних сборок; реализаций этих адаптеров в MVP нет. Для untrusted JavaScript нужен **отдельный origin**, sandboxed iframe, строгий allowlist источников, ограниченный версионированный postMessage-протокол с проверкой origin/source, CSP и аудит публикации. Нельзя передавать cookie, Auth.js JWT, пароли или административные endpoints в runtime.

Текущая CSP запрещает iframe и произвольные внешние скрипты; сетевые соединения разрешены только с самой платформой и настроенным origin Colyseus. Произвольная загрузка ZIP/JS, eval, dynamic import пользовательского пути и исполнение shell-команд не поддерживаются.

## Multiplayer

Сетевые возможности manifest, общий SDK, server registry и инструкция подключения авторитетного адаптера описаны в [Multiplayer](multiplayer.md). Транспортный SDK типизирован по состоянию, вводу и внедряемому драйверу предсказания; он не создаёт гонку самостоятельно. `RacePrediction` подключается только адаптером MIDNIGHT OUTLAWS. `server/registry.ts` содержит явные импорты допустимых room-классов, `PlatformRoom` — общие метаданные для admission, party и presence. Для новой игры зарегистрируйте собственный room/симуляцию, используя общие аккаунты и социальную инфраструктуру.

## Общий ввод

Используйте [NexusInputManager](controllers.md) вместо собственного опроса `navigator.getGamepads`. Root платформы уже запускает менеджер. Во время игры удерживайте scope `game`, освобождая его при паузе и выходе; `InputNavigation` делает это в текущих адаптерах. Читайте аналоговые значения в игровом цикле, а не через React state:

```ts
const controls = nexusInput.read();
const command = {
  throttle: controls.accelerate,
  brake: controls.brake,
  steer: controls.steer,
  nitro: controls.boost > 0.5,
  handbrake: controls.handbrake > 0.5,
};
if (nexusInput.consume('pause', 'my-runtime')) openPauseMenu();
```

В MIDNIGHT OUTLAWS клиентская симуляция и отправка нормализованных команд работают отдельным тактом 30 Гц через `FixedStepClock`, независимо от RAF отрисовки. Этот такт читает `nexusInput.readFresh()`; обычный опрос консольного интерфейса остаётся в RAF. Догоняющие шаги ограничены, при возврате из паузы часы сбрасываются. Локальная поза интерполируется при отрисовке, удалённые машины — сетевым SDK. Не связывайте скорость симуляции новой игры с частотой React render или тяжестью GPU-кадра.

Для своего runtime используйте уникальное имя потребителя одноразовых действий. Реагируйте на событие `disconnected` активного устройства: single-player открывает паузу, multiplayer сохраняет сессию и отправляет нейтральные команды. Менеджер сам обнуляет потерянный ввод и требует отпустить кнопки перед повторным включением. Для подсказок используйте `InputGlyph`; для необязательной вибрации — `haptic`, без предположений об actuator. Сетевой адаптер отправляет команды с собственной ограниченной частотой, проверка разрешённых действий остаётся на сервере.
