Проверялись масштаб автомобиля и архитектуры, читаемость разметки и HUD, фактура асфальта, контраст света, отсутствие обрезанных действий и горизонтального переполнения. По кадрам исправлены микрорельеф краски, яркость заднего света, слишком контрастные мелкие мокрые пятна, ориентация фасадов, композиция фото-камеры и раннее снятие Motion-анимации. В карусели фиксированные места карточек предотвращают сдвиг соседей. Одиночная пауза сохраняет кадр и освобождает GPU для навигации.

Production build, TypeScript и ESLint проходят; Vitest — **43 теста / 7 файлов**, Playwright — **16 из 16 в общем прогоне, 6,8 минуты**. [Журналы проверок](checks.txt). Частые повторы на одной QA-базе могут упереться в настоящий лимит регистраций; итоговый общий прогон использовал отдельную чистую базу, без отключения защиты.

После проверок собственная QA-база и её закрытый cookie-файл удалены. Основные PostgreSQL и Colyseus healthy, веб-приложение запущено на порту 3000; [финальная проверка основных HTTP endpoints](main-smoke.json) вернула 200, неавторизованного пользователя, пустую личную библиотеку и корректные статусы каталога. Cloud draft обновлён; публикация конфигурации остаётся отдельным действием в настройках среды.

Сетевой сценарий работает при логическом viewport 960 × 650; длинное лобби прокручивается, включая навигацию контроллером. Для снимков лобби и результатов окно после финиша увеличивается до 1280 × 900, UI захватывается при DPR 1. Фоновый WebGL этих двух снимков сохраняет сниженное тестовое разрешение. Повторный сетевой сценарий с этим захватом также прошёл (2,6 минуты). Индикатор ping на кадрах снят под нагрузкой SwiftShader и не характеризует задержку реального WAN или региона Europe. Отдельный игровой снимок High использует обычный DPR устройства 1.

## Измерения

Среда: Linux, Node.js 24.19, Chromium 154 headless, ANGLE / SwiftShader Vulkan. **Физической видеокарты нет.** Это замер программного WebGL, не прогноз скорости на GPU пользователя. Цель 60 FPS на подходящей видеокарте пока не подтверждена. В этой среде полноценная PBR-сцена работает медленно даже на Low; включённое аппаратное ускорение и отдельная проверка целевого оборудования необходимы для оценки играбельности.

Фактически получено: Low **1,7 FPS**, Medium **0,9 FPS**, High **0,6 FPS**, Auto → Low **3,1 FPS**. Автоматический режим уменьшал backing DPR до 0,6. Это короткие измерения программного рендерера на лимите четырёх CPU; результаты не доказывают производительность на физическом GPU и не соответствуют целевым 60 FPS.

Все четыре режима измеряются отдельно при viewport **960 × 640, DPR устройства 1**, с уменьшенной анимацией, без параллельных браузеров и сборок. Автоматизированный контроллер подаёт обычные газ и руление через Gamepad API, не изменяя физику или позицию машины. Активный участок длится минимум 20 секунд и до получения восьми окон; фактическая длительность сохранена в `measurementWallMs`. Данные выдаёт сам рендерер примерно раз в секунду; на очень медленном кадре окно длиннее. Первые два активных окна исключаются из сводки. В Auto меняется разрешение backing buffer; фактический диапазон DPR сохранён в JSON.

[Таблица результатов](performance-table.md), [машиночитаемая сводка](performance-summary.json). Полные измерения: [Low](performance-low.json), [Medium](performance-medium.json), [High](performance-high.json), [Auto](performance-auto.json). Отдельно сохранён [исторический Low до объединения геометрии](performance-before-batching.json). Между этими запусками менялись также материалы, дальность и клиентский такт; это не контролируемое A/B-сравнение и не данные предыдущей версии с примитивами.

FPS, средний кадр и p95 в таблице вычисляются из сырых `frameTimesMs` после двух начальных окон; p95 использует ближайший ранг `ceil(0.95 × N)`. `renderCpuMs` измеряет подачу команд CPU, не GPU timer query. Draw calls усредняются по кадрам в точках измерения; они включают проходы теней, отражения и постобработки. CDP JS heap — память JavaScript, не VRAM и не полная память процесса. `processMemory` дополнительно фиксирует Linux RSS и peak RSS браузерных процессов, включая GPU-процесс SwiftShader; это тоже не VRAM. `decodedBodySize` — объём HTTP-ресурсов после транспортного сжатия, не размер распакованных GPU-текстур. Загрузка ассетов и готовность runtime после первой подачи команд отрисовки измеряются отдельно; GPU fence и физическое появление кадра на мониторе не измеряются.

## Воспроизведение

Используйте отдельную мигрированную и заполненную seed базу. Запустите production web и отдельный игровой сервер с одной конфигурацией этой базы; команды в [README](../../README.md). `visual-qa.mjs` создаёт собственный аккаунт с префиксом `visual_` и хранит cookie в закрытом файле `/tmp/nexus-visual-browser-state.json`; не используйте этот инструмент против рабочей базы. После смены тестовой базы удалите этот файл. Сам скрипт не удаляет базы.

```bash
VISUAL_QUALITY=high npm run visual:qa -- capture
npm run visual:qa -- console
for quality in low medium high auto; do
  VISUAL_DRIVE=1 VISUAL_QUALITY=$quality VISUAL_WIDTH=960 VISUAL_HEIGHT=640 npm run visual:qa -- benchmark
done
node scripts/report-visual-performance.mjs
```

Можно задать `TEST_BASE_URL`, `CHROMIUM_PATH`, `VISUAL_WIDTH`, `VISUAL_HEIGHT`. Изображения и отчёты сохраняются в эту директорию. Потребность в сети относится только к необязательному импорту художественных источников; обычный runtime загружает GLB, текстуры, шрифты и декодер локально.

## Границы проверки

Автоматизированные действия контроллера используют эмуляцию Gamepad API. Физические DualSense, DualShock, Xbox, Nintendo, Bluetooth, вибрация, настоящий GPU и игра через публичный WAN не проверены. Функциональные E2E на SwiftShader используют явно заданный уменьшенный DPR; это не визуальные или скоростные тесты. Игра сохраняет одну компактную трассу, повторное использование трёх архитектурных моделей и упрощённую физику. Утверждений об AAA-качестве нет.
